# Переход клиентского приложения на ManagerSL

## Канонический процесс

Мобильное приложение больше не создаёт аккаунт до анкеты и не отправляет отдельную сущность `Application` из публичных экранов.

1. Пользователь открывает приложение без регистрации.
2. Черновик анкеты хранится только локально.
3. Готовая анкета отправляется в ManagerSL через `/api/client/v1/onboarding/submissions/`.
4. Для абитуриента обязательны 3–5 ВУЗов и 3–6 программ; для школьника выбор ВУЗов не требуется.
5. Приложение хранит `public_id` и секретный токен анкеты в защищённом хранилище и показывает статус проверки.
6. Повторная отправка той же анкеты блокируется. Исправление разрешается только после решения `changes_requested`.
7. После одобрения ManagerSL создаёт CRM-клиента, заявки по ВУЗам и SL-ID.

## Выведено из мобильного приложения

- самостоятельная регистрация;
- публичная форма отдельной заявки, дублировавшая анкету;
- серверное сохранение черновика анкеты в ClientsServer;
- генерация документа анкеты и загрузка её вложений через ClientsServer.

Каталог ВУЗов и программ уже читается из публичного API ManagerSL. Старый backend в каталоге `backend/` пока сохраняется для авторизации существующих пользователей, документов, уведомлений и других ещё не перенесённых функций. Удалять его целиком можно только после появления клиентской авторизации, FCM и остальных необходимых API в ManagerSL.
